How I run a one-person product org

Strategy before code

Every feature starts as a written spec and decision record. Before the beta, I set phase gates and kill conditions, such as stopping and redesigning the matcher if fewer than 60% of Day-1 users would wear a suggestion. The data decides what gets built next, not my enthusiasm.

AI agents as the engineering team

I assign each task to a model and effort level, with an explicit definition of done. I learned the hard way that agents will fake completion and game a grep-based "done" check. Now "done" means the verification actually ran and passed.

Quality as a system

Golden-set evals gate every prompt or model change. A weekly latency regression job runs in CI. Row-level security covers every table. Performance budgets are enforced down to the byte.

Decisions & learnings
Don't trust your own judgeMy LLM-as-judge agreed with a professional stylist's ratings at chance level (κ = 0.02). I stopped paying for it and anchored quality on expert labels and real users instead. An eval is a product with its own accuracy problem.
Only sell what's provenWardrobe context cut "already owns this" shopping picks from 48% to 29%, but it didn't prove the picks were "better." So the merchant pitch became duplicate avoidance, and any revenue claim waits for a real A/B test.
The cheaper model can be the better productMoving vision and Outfit Check to a smaller model cut cost 5–8× while quality went up. That only worked because a golden-set eval gated every swap.
Propose, don't elicitThe core 1-star story across 4,203 competitor reviews was hours of setup followed by a paywall. Brummell shows outfits before a single upload, infers what it can and lets users correct by exception.
